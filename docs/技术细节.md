# 技术细节

这份是给想改代码、或者遇到怪问题要往下挖的人看的。只想用插件的话看 [README](../README.md) 就够了。

## 两层结构，两层缓存

```
群消息 → meme-plugin（认关键词、拼参数、出网格图）
              ↓ HTTP
        meme-generator（真正画图的 Python 服务，默认 2233 端口）
              ↓ 读
        表情包仓库（config.toml 里的 meme_dirs 指向的一堆目录）
```

插件侧还存了一份**表情索引**（`data/meme-plugin/keyMap.json` + `infos.json`），
启动时直接从磁盘载入，不用等服务。所以「服务没了但索引还在」时，列表、搜索、网页版
会照旧显示满满 944 个表情，只有真发指令那一刻才报连不上。

这就是为什么 `#meme卸载` 收尾要**再探活一次**：连不上才 `MemeIndex.clear()` +
清三层出图缓存（`list_cache` / `preview_cache` / `thumb_cache`），让列表直接空掉；
还连得上（用户自己另有一套服务、或 `memeApiUrl` 指着别的机器）就一个字节都不动。
**「显示不出来」远比「显示得出来但用不了」好懂。**

同理，任何「让服务消失」的操作都得记住有两层，别只清一层。

## 表情更新的三个必过环节

`git pull` 成功 ≠ 新表情能用。缺任何一环都是「更新成功但没效果」：

1. **仓库拉下来** —— 且要拉到画图服务真正读的那个目录（`reposDir`）
2. **目录登记进 `config.toml` 的 `meme_dirs`，并重启画图服务** ——
   meme-generator **只在进程启动时扫描** `meme_dirs`，不热加载
3. **刷新插件侧索引** —— 关键词匹配完全依赖 `keyMap.json`，不刷新照样打不出来

`#meme更新` 一条指令走完这三步（外部服务时退化成只做第 3 步）。

重启后有约 **7 秒的空窗**，但表现不是「返回的表情数很小」而是**连接直接被拒** ——
meme-generator 是**扫完 `meme_dirs` 才开始监听**的。所以一旦 `/memes/keys` 能响应，
拿到的就已经是完整列表，「等 HTTP 通了再刷索引」不会读到残缺数据。
反过来说，这期间的失败别误读成「表情丢了」。

## pm2 的进程名不能用数字

`memePm2Name` 必须写名字。pm2 的数字 ID 会随进程增删而漂移 —— 曾经写死 `pm2 restart 2`，
而那台机器上 ID 2 是另一个无关服务，结果每次都在重启别人，meme 服务的 `restart_time`
一直是 0、从未重启过，新表情永远加载不进去，而且**完全没有报错**。

判定方法：`pm2 jlist` 看目标进程的 `restart_time` 有没有涨、运行时长有没有归零。

## config.toml 在哪，为什么

位置不是插件定的，是 meme-generator 用 nonebot `plugin-localstore` 那套规则算出来的
（`user_config_dir`，`roaming=True`）：

| | 位置 |
|---|---|
| Linux | `$XDG_CONFIG_HOME/meme_generator/`，未设则 `~/.config/meme_generator/` |
| macOS | `~/Library/Application Support/meme_generator/` |
| Windows | `%APPDATA%\meme_generator\`（**Roaming**，不是 Local） |

插件的 `utils/memeDirs.js` 按同一套规则定位，`#meme更新` 才能把 `meme_dirs` 写进服务
**真正会读**的那个文件。曾经 `deploy.sh` 里把它写死成 `$HOME/.config/meme_generator`，
既不吃 `XDG_CONFIG_HOME` 也没处理 macOS，症状是「部署全绿但只有内置表情」—— 写进了
一个没人读的文件，5 个仓库白拉。

venv 里可执行文件的位置也有差异：Linux/macOS 是 `venv/bin/meme`，Windows 是
`venv\Scripts\meme.exe`；一键部署脚本对应 `deploy.sh` 与 `deploy.ps1`。

## Windows / PowerShell 上绕开的坑

`deploy.ps1` 与 `deploy.sh` 逐步对照实现、输出同一套 `::STEP::` 标记，
两边都在真机上跑通过完整的部署 → 卸载。

优先用 **pwsh（PowerShell 7）**，找不到才退回系统自带的 `powershell.exe` 5.1。
5.1 那条路上有四处语义差异，都已绕开：

| 坑 | 症状 | 绕法 |
|---|---|---|
| `-File` 会把命令行上的空字符串**直接丢掉** | `gitProxy` 留空导致后面参数整体前移、`[int]$Port` 绑定失败，退出码 1 且一个字都不输出 | 全部改用命名参数 |
| 传给原生命令的参数里**双引号被吞** | 探 Python 版本的代码被截断，装着 3.11 也报「需要 Python 3.9+」 | 那行写成零引号的 `sep=chr(46)` |
| `Set-Content -Encoding UTF8` **带 BOM** | meme-generator 的 toml 库直接 `open()` 读，BOM 让首行 `#` 注释被当成 key，服务启动就抛 `Found invalid character in key name: '#'`，pm2 反复重启到 errored | `config.toml` 改用 .NET 显式写成无 BOM |
| 5.1 读 .ps1 不认无 BOM 的 UTF-8 | 中文变乱码 | 脚本本身存成**带** BOM |

另外两件事：**组策略**下发的 ExecutionPolicy 拦下 .ps1 时，命令行上的
`-ExecutionPolicy Bypass` 是无效的 —— 会自动改用 `-EncodedCommand` 把脚本正文内联执行重试一次
（注意命令行总长上限 32767，脚本正文快顶到了）。部署失败时 PowerShell 的 stderr 会一起回给你
（CLIXML 包装已还原成人话），不再只有一句退出码。

## PATH 继承：装了却报「缺少」

Yunzai 进程的环境变量停在它**启动那一刻**。之后装 Python、`npm i -g pm2` 写进注册表的新 PATH，
已经跑着的进程、以及它拉起来的 PowerShell 子进程都看不见。所以 git（装在 `Program Files`、
开机就在系统 PATH 里）找得到，后装的 pm2（`%APPDATA%\npm`）和 Python 找不到。

部署脚本和插件调 pm2 的地方都会自己补救：从注册表读 Machine + User 的 Path 合进本会话，
再按 `%APPDATA%\npm\pm2.cmd`、`py -0p` 登记的解释器、`%LOCALAPPDATA%\Programs\Python\Python3*`
这些常见位置翻一遍。**`WindowsApps` 下的 `python.exe` 要排除** —— 那是微软商店的占位存根，
跑起来只会弹商店。同样的问题在 Linux 上换个形式出现：nvm 切了 node 版本后老进程照旧用旧路径。

## 卸载的安全边界

`#meme卸载` 是插件里唯一会删东西的指令，判据是实测定下来的：

**pm2 归属必须 `pm_exec_path` OR `pm_cwd` 双判**，光比进程名会删错东西 ——
`deployPm2Name` 被误填成别人的进程名（甚至就叫 `meme`）时，按名字 `pm2 delete`
会把人家手工装的服务连 dump 一起抹掉。两个字段都要看是因为：
`--interpreter venv/bin/python` 起的进程 `pm_exec_path` 不指向 venv，
而 `pm_cwd` 是**发起 pm2 命令时的 cwd**、不是脚本所在目录，单看任一个都会漏。

**`pm2 delete` 之后必须 `pm2 save`**，否则 `~/.pm2/dump.pm2` 里还留着，机器重启又被拉起来。
（`dump.pm2` 是 JSON，但 `require()` 按 `.pm2` 后缀当 JS 解析会报错，得 `readFileSync` + `JSON.parse`。）

**Windows 上表情素材目录和 `config.toml` 是同一个目录**（都在 `%APPDATA%\meme_generator`），
所以「删素材」会连配置一起删掉。Linux 才分开（`~/.local/share` vs `~/.config`）。
因此素材目录**只报告、不删**，跨平台统一。

**先停进程再删目录**。反过来在 Windows 上必炸：venv 里的 `meme.exe` 正在跑，
`rmSync` 报 EBUSY/EPERM，删一半留一半更难收拾。删除带 6 次重试，因为进程刚停时句柄常还没释放。

`config.toml` 优先还原部署时留下的 `.bak.*` 备份（有多个取时间戳最新的，备份本身留着），
没备份才删；首部**没有插件写的标记**就一个字节都不动 —— 那是用户自己的配置。

`reposDir` 指到插件目录外时，外面那份仓库一个字节都不动；但 `data/meme-plugin/repos`
里可能还留着早先克隆的副本，它在插件数据目录里，归卸载管。

## 出图为什么只放 8 个

**决定观感的不是渲染多大，是 QQ 气泡的显示上限。** 实测图片最宽只显示约 **420px**，
宽高两个上限同时生效、按 contain 缩放。于是每格实际宽度 = `420 ÷ 列数`：

| 一张图放几个 | 列数 | 每格 | 标签字号 | 能不能读 |
|---|---|---|---|---|
| 5 | 4 | 105px | 8.4px | 勉强 |
| 24 | 6 | 70px | 5.7px | 费劲 |
| 80 | 12 | 35px | 2.9px | 完全不能 |

名字要可读需要每格约 105px → 最多 4 列 → 再满足下面的比例约束只能排 2 行，
所以**一张 QQ 图最多清晰承载 8 个表情**。超过就把名字**另外用文字发一份**
（文字不受缩放影响，还能直接复制）。

**宽高比必须 ≥ 约 1.15。** 图比气泡的「最大宽/最大高」（实测约 1.1）更高时，缩放由高度决定、
宽度顶不满，看起来比下面那行链接短一截。所以列数取「宽高比达标的最小列数」。
改帮助图文案后要**重新量一次宽高比** —— 填充内容多一行少一行就会把 1.175 拉到 1.142 不达标。

两个渲染上的坑：`page.screenshot({fullPage:true})` 会**补白边**（内容 476px 高、
viewport 600px 就硬补 124px，还把宽高比读数算歪），改成截 `body` 元素才精确贴合；
标签必须 `-webkit-line-clamp: 2` 限死两行，否则长关键词换行会把整行撑高、按 CELL_H 估的列数全飘。

## 网页版的性能与限流

**预览图体积是硬伤**：服务端 `/memes/{key}/preview` 平均 **281KB**、最大 1.38MB，
全量约 **230MB**。直接在列表里加载原图，手机上必然卡死。两层处理：

- `model/preview.js` 用 **sharp**（Yunzai 自带，零新增依赖）压成 webp，`animated:false`
  只取首帧，宽 260 / quality 72，压缩率 **98~99.7%**（1.38MB → 10.7KB），全量降到约 3MB
- 前端用 **IntersectionObserver** 手动控 `img.src`（`rootMargin:300px`）。
  只靠 `loading="lazy"` 不行 —— 近千个 `<img>` 插进 DOM 后浏览器仍会预取一大批
- 路由分工：列表走 `/memes/thumb/:key`（压缩图），详情弹层才走 `/memes/preview/:key`（原图）

服务端 preview 无缓存，所以两层都要自己存盘。

**在线生成是唯一消耗算力的入口**，而站点无鉴权，所以三道闸：

| 闸 | 值 | 为什么 |
|---|---|---|
| 每 IP 每分钟次数 | `webMakeLimit`，默认 10 | 挡脚本连点 |
| 同时进行数 | 固定 2 | 画图服务是单进程 Python，堆并发只会一起变慢 |
| 单次请求体 | `maxFileSize × 1.4 × 图片位数`，封顶 50MB | 图走 base64 会涨 1/3；9 图的表情不封顶能算到 126MB |

传图走 JSON + base64 而不是 multipart，是为了让「本地文件」和「QQ 号取头像」两种来源
在同一个请求里混用。注意**别在读完 body 前 `req.destroy()`**，那会吞掉 413 响应，
浏览器只看到连接被掐、报不出「文件太大」。

## 关键词匹配与兜底规则

1332 个关键词合并成**一条** `^#` 规则、`priority` 5000 排最后，未命中 `return false` 放行。
实测 20 个常见指令（`#帮助` `#更新` `#状态` `#签到` `#面板` …）**零误吞**。

**必须按长度降序匹配**：1332 个关键词里有 51 个短词会吃掉 75 个长词
（「摸」吃「摸鱼」、「跳」吃「跳舞」），最长匹配才能都打得出来。

表情黑名单的过滤做在**索引层**，所以生成、搜索、分类、列表、随机、网页版一处配置全生效；
按中文别名拉黑时屏蔽的是背后**整个表情**，换个别名绕不进来。

## 表情包仓库之间重复得厉害

meme-generator 按表情 key **全局去重、先加载的赢**。加仓库前先量净增量：

- `crazy_emoji` 与同作者 `meme_emoji_nsfw`：36 个 key **完全一样**，两个都装净增 **0**
- `tudou-meme`：自带 111 个，净新增 **107**

**表情的 key 来自源码里 `add_meme("key", ...)` 的第一个参数，不是目录名**，别拿目录名去比。
另外各仓库的 `memeSubDir` 不一样（`emoji` / `memes` / `meme`），填错会让 `meme_dirs`
指向不存在的路径，服务扫不到表情。

**`gitProxy` 建议留空。** 这类 GitHub 前缀镜像（`https://xxx/https://github.com/...`）经常整体失效，
挂掉时表现为 git 报 403 / 522 / 直接卡死，很容易误判成网络不通。机器上已有系统级代理时，
留空直连最稳。

## 手动部署（不用 `#meme部署`）

```bash
python3 -m venv venv && ./venv/bin/pip install "meme-generator<0.2"
./venv/bin/meme download          # 下载内置表情素材
pm2 start ./venv/bin/meme --name meme -- run && pm2 save
```

**版本必须锁 `<0.2`**：0.2.x 是重写成 Rust 的库，**不再提供 HTTP 服务**，装上去插件没法用。

再把表情仓库克隆到任意位置，写进 `config.toml` 的 `meme_dirs`（位置见上文），
然后重启服务。用 pm2 起是为了能被 `#meme更新` 重启；用别的方式守护也行，
那就把 `serviceMode` 设成 `remote`，`#meme更新` 会退化成只刷索引。

> `serviceMode: auto` 只看服务地址是不是回环地址（`localhost` / `127.*` / `::1` / `0.0.0.0`）。
> **唯一判不出来的是本机 docker** —— 地址是 127.0.0.1，但仓库和 `config.toml` 在容器里面，
> 这种要手动设 `remote`。

## 代码结构

```
apps/       指令入口（生成 / 列表 / 搜索 / 开关 / 排行 / 更新 / 部署 / 卸载 / 帮助）
model/      配置（双文件合并 + chokidar 热重载）、API 封装、表情索引、预览图、用量统计
utils/      参数解析、文件、网格出图、详情出图、榜单出图、meme_dirs 同步、黑名单与群开关
server/     网页版 + 站内生成接口
resources/  Web 前端 + 一键部署脚本（deploy.sh / deploy.ps1）
constants/  路径常量（dataDir 由 process.cwd() 推出）
config/     system/ 是默认值，同级 config.yaml 是用户配置（已 gitignore）
```

`index.js` 动态加载 `apps/`。配置读的是「默认值 + 用户值」合并结果，
所以往 `config/system/config.yaml` 加字段**不会**重置用户已有配置。

## 数据目录

```
keyMap.json / infos.json   表情索引，启动时从这里载入（第二层缓存）
stats.json                 用量统计，内存累加 + 5 秒防抖写盘
preview_cache/             原图预览缓存（服务端没有缓存，本地存一份）
thumb_cache/               压缩后的网格缩略图
list_cache/                列表 / 搜索 / 分类的成品出图
original/  result/         生成表情时的临时文件，用完即删
repos/                     表情仓库（仅 reposDir 留空时）
venv/                      一键部署创建的 Python 虚拟环境
```

清理规则按寿命分三档：`original`/`result` 正常路径当场删、这里只兜漏（进程被 kill 留下的）；
`list_cache` 会被翻页反复命中，留一天；`preview_cache`/`thumb_cache` 越攒越值钱，
不按时间清、只卡 `maxCacheMB` 容量，淘汰最久没读到的。每 6 小时跑一轮。

## 怎么测

脱机跑 `apps/` 里的指令要打桩 `logger` / `plugin` / `segment` / `Bot`，
且 **cwd 必须在 Yunzai 根目录**（`dataDir` 是从 `process.cwd()` 推出来的），
结尾要 `process.exit(0)` —— `model/config.js` 顶层的 chokidar watcher 会挂住进程。
`logger` 桩必须在业务模块 import **之前**设好，所以要用动态 `await import()`
（ESM 静态 import 会被提升到最前）。

反过来利用这一点就能**隔离测试**：把 cwd 换到 `/tmp/xxx`，`dataDir` 就跟着换过去，
删缓存之类的破坏性逻辑可以放心跑。测 `config.toml` 相关逻辑则设
`XDG_CONFIG_HOME=/tmp/xdgtest`（Linux 上 `tomlPath()` 认这个变量）。

**验证基线**（改完照这个复验，当前规模 944 表情 / 1332 关键词）：

- 关键词自匹配 0 失败
- 短词抢长词回归：跳舞 / 摸鱼 / 抱大腿 / 举牌 / 敲黑板 / 玩游戏 / 舔糖 / Deepseek说 全过
- 带参表情 POST 服务全部 < 300
- 前端 puppeteer：JS 0 错误、卡片 0 溢出、手机 2 列 / 1280px 5 列

## 报错文案

undici 的连接类失败 `err.message` **恒为 `fetch failed`**，真实原因在 `err.cause.code`
（ECONNREFUSED / ENOTFOUND / EHOSTUNREACH / EAI_AGAIN / UND_ERR_*），超时则是
`err.name === 'AbortError'`（不带 cause）。`model/memeApi.js` 的 `netError()`
统一在 `request()` 的 catch 里翻译成带地址、错误码和下一步指引的人话 ——
原样抛出去用户只看到五个英文单词，既不知道哪个地址连不上，也不知道该改配置还是起服务。

空态文案要区分「一个表情都没有」和「搜了没命中」：前者给
「有服务就 `#meme刷新` / 没服务就 `#meme部署`」两条出路，别只写「请先发 #meme更新」——
卸载后发它只会再撞一次连不上。
